# v0.5 地图编辑室

## 使用

1. 打开 `/author/`，用现有 Access 邮箱登录。
2. 从“编辑地点”选择原有地点，或点“新增地点”。
3. 填写名称和地区。在总览地图点击位置，或切到街道底图放大后选点；也可手工填写经纬度。地址说明是文字备注，不会自动地理编码。
4. 添加照片（最多 20 张）、旅行日期、故事、署名和半星评分。可以移出照片或设为封面。
5. 保存云端草稿只对作者可见；“发布到地图”会让全部访客看到。切换地点或离开页面时会提醒未保存修改。并发修改有版本冲突保护，不会静默覆盖。
6. 首页“排列方式”可选默认、星级降序、星级升序。未评分始终排最后，0 星是有效评分，同分保持原顺序。排序与地区、文字筛选同时生效。

## 部署

继续使用 Pages 的 `exit 0` / `public`，根目录 `functions` 不移动。D1 绑定 `DB` 和四个 Access 变量不变。

`migrations/0002_places.sql` 为纯新增表结构。首次经过身份与 CSRF 校验的保存或照片上传会自动执行同样的 `CREATE TABLE IF NOT EXISTS`，无需手工运行 SQL。读取不存在的新表时返回空集合，保留原网站数据。

原 `author_reviews` 表及 `public/data/memories.json` 不删除或覆盖。公开页按“打包地点 → 旧云端评价 → 新云端地点”合并。旧后台草稿会在第一次进入新编辑器时保留为待迁移内容。

## 照片与边界

为避免新增服务配置，本轮压缩照片保存于现有 D1，最长边 1280 像素且每张 JPEG 不超过 200 KiB（base64 存储约 267 KiB），不是原图托管。浏览器重绘去除 EXIF 等元数据，原图需自行保留。此实现适合个人小相册；大量照片应另行迁移到对象存储。

参考 [D1 官方限额](https://developers.cloudflare.com/d1/platform/limits/)：单行/字符串限制 2 MB。本轮单张数据远低于该值，仍受数据库总容量和读写配额限制。

上传后只有作者接口可读取素材；公开图片接口只返回被已发布地点引用的图片。移出相册不销毁数据库素材，避免误删和其他地点引用丢失；未引用素材暂不自动清理。草稿和图片响应均不缓存。

本轮不含地点删除、地址搜索服务或原图下载。输入坐标限定英国及周边（经度 -15～12、纬度 46～65）。

## 验证

- `npm run check`：身份、CSRF、地点校验、增量迁移、草稿隔离、并发版本、图片发布权限、评分排序。
- `node tests-v04/browser-server.mjs`：只监听本机的独立 SQLite / 签名身份测试服务器，不接触线上数据。
- `node tests-v04/editor-browser.mjs`：使用 Playwright，可由 `PLAYWRIGHT_MODULE`、`CHROMIUM_EXECUTABLE` 指定本机依赖。测试地图选点、街道模式、照片上传、新建、草稿重载、发布、公开图片、深链接、排序及多屏宽布局。
- `wrangler pages functions build functions --outfile <临时输出文件>`：Pages Functions 打包检查。

旧 `browser-check.py` 是 v0.4 的离线注入测试，仅作历史参考；v0.5 使用上述真实本机 HTTP 浏览器测试。
